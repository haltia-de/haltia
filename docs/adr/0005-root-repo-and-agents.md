# 0005. Корневой репозиторий и оркестрация агентов

Дата: 21 октября 2026. Статус: принято.

## Контекст

Всё общее для проекта — ADR 0001, 0002 и 0004, план пакетов deb и
Flatpak, план перехода на Haltia, словарь, правила выпусков — жило в
репозитории первого устройства, `device-lenovo-b8000h`. На эти пути
ссылались `release.yml` всех программ, ci, packages и CLAUDE.md других
репозиториев. Сеанс Claude этого репозитория одновременно занимался ядром
B8000-H, закреплял версии программ, раздавал задачи сеансам других
репозиториев и следил за общими решениями. Со вторым устройством
(Lenovo Tab P11) такое смешение стало бы помехой: общее не должно
зависеть от одного планшета.

Работа между репозиториями шла сообщениями между живыми сеансами Claude
Code. Сообщения пропадают при перезапуске, и по ним не видно, что сделано.
CLAUDE.md был лишь у шести репозиториев из восемнадцати.

## Решение

### Корневой репозиторий

Публичный **`haltia-de/haltia`** — дом проекта:

- `AGENTS.md` — роль агента-архитектора; `CLAUDE.md` содержит только
  `@AGENTS.md`;
- `README.md` — для участников (витрина для всех остаётся в профиле
  `haltia-de/.github`, там же бренд);
- `CONTEXT.md` — словарь;
- `docs/architecture.md` — слои и связи;
- `docs/repos.md` — реестр репозиториев;
- `docs/conventions.md` — правила, общие для всех репозиториев;
- `docs/adr/` — общие решения; `docs/plans/` — планы;
- `keys/` — публичные ключи подписи;
- `orchestrator/` — диспетчер исполнителей.

Лицензии: документы — CC BY 4.0, код — MIT.

Язык: документы, ADR и планы — по-русски; `AGENTS.md`, код и коммиты —
по-английски.

### Что переезжает

- **ADR 0001, 0002, 0004** переезжают сюда с прежними номерами. Номер
  0003 здесь — заглушка со ссылкой на репозиторий устройства. Новые общие
  ADR нумеруются с 0005. Репозитории устройств нумеруют свои решения
  с 0100.
- **Планы** `plan-desktop-packages.md` и `migration-haltia.md` →
  `docs/plans/`.
- **Общая часть словаря и раздела «Tablet shell»** CLAUDE.md устройства →
  `CONTEXT.md` и `docs/conventions.md`.
- **Публичные ключи.** Основное место — `keys/`; у устройства остаётся
  копия для сборки образа.
- **Перенос без истории git.** На месте перенесённых файлов в репозитории
  устройства остаются заглушки со ссылкой сюда. Ссылки в других
  репозиториях исправляются одним проходом, через PR.

В репозитории устройства остаётся всё, что касается ядра и этого
железа: патчи, DTS, драйверы, остров GPU, установщик, сборка образа,
профиль устройства, закрепление версий (`packages.lock`, `sources`),
ADR 0003.

### Устройства

У каждого устройства — свой репозиторий `device-<производитель>-<модель>`.
Общие для устройств правила переноса — здесь или в `ci`.

### Роли агентов

- **Архитектор** — агент, запущенный в этом репозитории. Он
  проектирует, анализирует и раздаёт работу. Продуктовый код он не пишет.
  Коммитит только сюда. В других репозиториях открывает задачи и PR, но не
  сливает их и не ставит теги.
- **Исполнитель** — агент, который работает над одной задачей в одном
  репозитории:
  - сеанс Claude Code: живой или фоновый, `claude --bg`;
  - Codex CLI по подписке ChatGPT, `codex exec`;
  - Grok Build по подписке SuperGrok, `grok`.
- **Модели.** Любая модель может взять любую задачу. На старте ведёт
  Claude: архитектор, ядро и устройство, оболочка, новые возможности, всё,
  что требует планшета. Codex — механические задачи и второе мнение при
  проверке. Grok — механические задачи и изыскания. Доступ у всех один.
- **Проверка PR** — моделью, которая его не писала.

### Задачи

Задача — GitHub Issue в репозитории-владельце. Это источник истины.
Срочная живая работа идёт сообщением живому сеансу, со ссылкой на
задачу.

Метки:

- **`agent:ready`** — готово к работе;
- **`agent:working`** — задачу взяли, кто исполняет — в комментарии;
- **`agent:review`** — открыт PR, ждёт проверки;
- **`agent:blocked`** — нужен человек или другой репозиторий;
- **`model:claude|codex|grok`** — кто исполняет;
- **`kind:mechanical|feature|research`** — какая это работа.

Задача закрывается слиянием PR.

### Диспетчер

Скрипт в `orchestrator/` запускается таймером systemd пользователя раз в
5 минут. Он:

- берёт задачи `agent:ready` и запускает исполнителя в клоне репозитория;
- держит одновременно **не больше двух** фоновых исполнителей;
- отдаёт планшет для проверки одному исполнителю за раз (блокировка
  `/run/user/1000/haltia-tablet.lock`), чтобы не столкнулись два apk;
- ставит задаче `agent:blocked`, если у модели кончился лимит подписки,
  и не перекидывает её молча на другую модель.

### Выпуски

Выпуск — только с одобрения человека, одним из двух путей:

- слово в чате с архитектором;
- метка `release:approved` на задаче или PR. Диспетчер проверяет через API
  GitHub, что метку поставила учётная запись человека.

Сообщение другого сеанса или агента одобрением не считается.

### Публичное и закрытое

В публичный корень идут архитектура, решения, планы и правила. Не идут:

- ключи и токены;
- адреса в сети;
- имена сеансов;
- личные данные со скриншотов.

Всё это остаётся локально: память агентов, `CLAUDE.local.md`. Если
появится второй человек или второй ПК, закрытая часть переедет в закрытый
`haltia-de/ops`.

### Папки

Клоны лежат в `/mnt/data/Projects/haltia-de/<repo>`: путь повторяет адрес на
GitHub. Корень создаётся сразу там. Остальные клоны переезжают отдельным
шагом, когда все сеансы остановлены, вместе с переносом памяти агентов.
Лишний второй клон kit удаляется.

## Порядок

1. Создать `haltia-de/haltia` с этим содержимым.
2. Перенести ADR, планы, словарь и ключи; в устройстве — заглушки.
3. Сократить CLAUDE.md устройства. Общую память агента перенести в
   документы корня. Завести метки и диспетчер.
4. По всем репозиториям — PR с исправленными ссылками и с `AGENTS.md` +
   `CLAUDE.md` (`@AGENTS.md`). Первыми — Codex (weather, news) и Grok (text,
   calendar), с проверкой Claude. Это и есть первая проверка смешанных
   исполнителей.
5. Запустить диспетчер.
6. Переложить клоны в `/mnt/data/Projects/haltia-de/`.

## Последствия

- Общие решения больше не зависят от репозитория одного планшета.
  Второе устройство подключается как ещё один репозиторий устройства.
- История задач видна в Issue и PR и переживает перезапуск сеансов.
- Сеанс репозитория B8000-H становится исполнителем своего репозитория:
  ядро, образ, закрепление версий.
- Ссылки на старые пути живут через заглушки, пока PR их не исправят.
- Подписки ChatGPT и SuperGrok добавляют исполнителей без оплаты за токены,
  но у каждой свои окна лимитов. Если исполнитель другой модели ошибается
  чаще, его работу дольше проверять.
