# 0006. Исполнители с ограниченными правами

Дата: 21 октября 2026. Статус: принято. Уточняет ADR 0005.

## Контекст

По ADR 0005 у всех исполнителей один доступ: каждый сам коммитит, пушит,
открывает PR и меняет метки. Для фонового запуска это значит запускать
Claude, Codex и Grok с отключёнными проверками (`--dangerously-*`,
`--always-approve`) и с токеном GitHub человека. Ошибка исполнителя
или чужой текст в задаче, принятый за указание, тогда может дойти до `main`,
тегов и выпусков.

## Решение

- **Исполнитель только правит файлы.** Он получает простую копию дерева
  ветки, без `.git` (клон диспетчера в `~/.cache/haltia-dispatch/`, не клон
  живого сеанса), и не коммитит, не пушит, не ставит теги, не вызывает GitHub и не трогает
  планшет. Текст задачи и комментарии диспетчер передаёт ему в задании.
- **Права по моделям:**
  - Claude — `claude -p` со списком `--allowedTools`: чтение и правка, без
    Bash (даже `git diff` с аргументами может писать файлы);
  - Codex — `codex exec -s workspace-write`: запись только в свою копию,
    без сети;
  - Grok — `grok -p --permission-mode acceptEdits`, без поиска в сети.
- **GitHub делает диспетчер.** После выхода исполнителя он коммитит изменения
  с сообщением исполнителя, пушит ветку `agent/<номер>`, открывает PR
  («Closes #N») и ставит `agent:review`. Ничего не изменилось или исполнитель
  написал `blocked` — `agent:blocked` с причиной.
- **Чужой текст.** В задание попадают задача и комментарии только тех, у
  кого есть право записи в репозиторий (проверка по API
  `collaborators/…/permission`), и они отмечены как данные, а не правила.
- **Git — только у диспетчера.** После выхода исполнителя диспетчер копирует
  его файлы в свой клон (без `.git`) и коммитит там, без крюков и fsmonitor.
  Метаданные git исполнитель не видит и не может подменить.
- **Планшет.** Задачи с меткой `needs:tablet` диспетчер не берёт: их делают
  живые сеансы, и блокировка `/run/user/1000/haltia-tablet.lock` — для них.
- Каждый исполнитель — отдельный юнит `systemd-run --user` с `MemoryMax` и
  предельным временем работы. Не больше двух одновременно и не больше одного
  на репозиторий.

## Последствия

- Исполнитель не может слить, выпустить или испортить чужую ветку: у него нет
  ни сети GitHub, ни права push.
- Задачи, где нужна сеть (зависимости, загрузки), исполнитель отмечает
  `blocked`; их делает живой сеанс или задача делится иначе.
- Проверка `release:approved` по учётной записи ничего не доказывает, пока
  живые сеансы работают с тем же токеном, что и человек: метку, поставленную
  агентом, нельзя отличить. Пока выпуск — только по слову в чате. Чтобы метка
  стала доказательством, агентам нужна своя учётная запись или GitHub App.
- Как Grok работает с инструментами в `-p`, ещё не проверено. До проверки
  задачи `model:grok` диспетчеру не отдаются.
