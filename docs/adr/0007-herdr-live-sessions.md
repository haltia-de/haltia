# 0007. Живые сеансы и ревьюер в herdr

Дата: 21 октября 2026. Статус: принято. Дополняет ADR 0005 и 0006.

## Контекст

Срочная работа в репозиториях идёт сообщениями живым сеансам (ADR 0005).
`SendMessage` связывает только сеансы Claude Code: живому Codex или Grok
так задачу не передать, и по сообщению не видно, занят сеанс, свободен или
ждёт ответа на вопрос.

На ПК сборки агенты работают в [herdr](https://herdr.dev) — менеджере
терминальных рабочих областей для агентов. Он:

- распознаёт Claude, Codex, Grok и другие агенты и знает их состояние:
  `idle`, `working`, `blocked`, `done`;
- принимает задание агенту по имени и ждёт, пока тот закончит
  (`herdr agent prompt … --wait`), отдаёт его вывод (`herdr agent read`);
- после перезапуска сервера или ПК восстанавливает панели и продолжает
  агентов в их же разговорах (`[session] resume_agents_on_restore`, по
  умолчанию включено). Для этого нужны свежие хуки интеграции агентов
  (`herdr integration status`).

Пробный ревьюер Codex в herdr 21 октября проверил PR weather#2 за 70 секунд.

## Решение

- **Живые сеансы репозиториев** работают в herdr как именованные агенты,
  по рабочей области на репозиторий. Имена агентов и рабочих областей — в
  локальной памяти, не в этом репозитории.
- **Архитектор передаёт им работу через herdr:** смотрит состояние
  (`herdr agent get`), отправляет задание со ссылкой на Issue
  (`herdr agent prompt … --wait`) и читает ответ (`herdr agent read`).
  `SendMessage` остаётся запасным путём между сеансами Claude.
- **Вопрос на экране агента** (`blocked`: подтверждение, доверие к папке)
  решает человек. Архитектор показывает вопрос и отвечает только с его
  согласия.
- **Ревьюер.** Для PR, написанных Claude, архитектор поднимает в herdr
  агента Codex только на чтение (`-s read-only -a never`) в отдельном клоне
  ветки PR (`~/.cache/haltia-review/<repo>`). Его выводы архитектор публикует
  комментарием в PR. Сеанс ревьюера живёт, пока нужен; закрыть его может и
  человек.
- **Задания диспетчера** остаются в юнитах `systemd-run` (ADR 0006).
  Интерактивный агент в панели спрашивает подтверждения, у панели нет
  `MemoryMax` и предела времени, а конец работы виден по интерфейсу, а не по
  коду возврата.

## Последствия

- Архитектор может передать срочную работу живому сеансу любой модели и
  видит, когда тот закончил.
- Перезагрузка ПК не обрывает живые сеансы, если хуки интеграции свежие.
- Живые сеансы в herdr работают с полными правами, как и раньше; ограничения
  ADR 0006 их не касаются.
- `read-only` у Codex запрещает только запись: сеть у ревьюера есть.
- herdr управляется только изнутри его панелей (`HERDR_ENV=1`): таймер
  диспетчера с ним не работает.
