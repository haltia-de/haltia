# 0012. Следующая модель при недоступности исполнителя или ревьюера

Дата: 29 октября 2026. Статус: принято автором в чате.
Меняет запрет автоматической смены модели из ADR 0005/0006 и вводит
исключение к порядку ревьюеров ADR 0008 при недоступности нужной модели.

## Решение

Если назначенная модель недоступна, выбирается следующая по цепочке
**Claude → Codex → Grok**. Причина и переход записываются в issue либо
результате ревью. Правило распространяется и на исполнителей, и на
ревьюеров; автор подтвердил это отдельно в чате.

### Исполнитель

Диспетчер распознаёт отсутствие CLI, явный лимит подписки/сервиса,
сообщение недоступности сервиса или необходимости входа. Он заменяет
единственную model-метку следующей, возвращает задачу в agent:ready и
завершает текущую попытку. Следующий обычный tick запускает отдельного
ограниченного исполнителя. Неизданные правки неуспешной попытки не
переносятся; уже опубликованная ветка PR остаётся исходной базой доработки.

После Grok задача получает agent:blocked и ждёт человека. Цепочка не
зацикливается, подписка не обходится, дополнительная покупка или иной
способ входа не предпринимаются. Ошибка приложения, тестов, инфраструктуры
с неустановленной причиной и потребность в устройстве сами по себе не
считаются недоступностью модели.

Перед изменением меток повторно проверяются открытое состояние задачи,
model-метка и agent:working; решение человека, изменившего их во время
исполнения, сохраняется. Разрешение на выпуск при смене модели не возникает.

### Ревьюер

Первый выбор ревьюера остаётся по ADR 0008. При его недоступности разрешена
следующая модель по той же цепочке, включая Codex после Claude и Grok
после Codex. Ревью выполняет независимая сессия, не автор изменений;
в записи указываются модель, причина замены, точный SHA, область, результаты
и ограничения по ADR 0011. Саморевью и отсутствие доступного независимого
ревьюера не дают разрешения на merge.

Остановка на вопросе доверия или разрешения не означает недоступность
модели: вопрос остаётся за человеком. Предписанные проверки и барьеры
публикации сохраняются при любом переходе.

## Проверка реализации

Тесты диспетчера запускают настоящий путь задания с изолированными
границами GitHub/CLI. Проверяются оба перехода по лимиту, отсутствие CLI,
недоступность сервиса, остановка на Grok, сохранение model при ошибке
приложения и отсутствие коммита частичного результата.
