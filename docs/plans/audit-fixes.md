# План исправлений по аудиту 21 октября 2026 (на согласование)

Аудит программ с упором на стабильность и производительность на планшете
(MT6589, Cortex-A7, 1 ГБ). Устройство и мессенджер не входили: там идёт
работа по [звонкам](calls.md).

Как делали: пять аудиторов Claude читали код и прогоняли тесты без экрана
(всего 80 замечаний). Второй проход перепроверял каждое замечание другим
ревьюером: свежий Claude — kit, files, text, calendar, video, music; Grok —
paint, news, weather, firefox; Codex — shell, ci, packages. Итог: почти все
замечания подтверждены, часть — частично (уточнены важность и исправление),
одно отвергнуто (PKG-9), найдено ещё 20. Ничего на планшете не измерялось:
оценки времени и памяти — по коду.

Отчёты целиком — в истории сеанса архитектора; здесь — сводка с
окончательной важностью после перепроверки.

## Волна 0 — срочно: выпуски и пакеты (ci, packages)

| ID | Что | Важность | Исправление |
|---|---|---|---|
| PKG-2 | Сайт пакетов 1,29 ГБ при лимите Pages 1 ГБ; GitHub уже предупреждает «Deployment might fail». Noarch-пакеты копируются в три архитектуры, старые версии не удаляются. | **критично** | Хранить последние N версий каждого пакета плюс закреплённые в `packages.lock` устройств; noarch — не копировать трижды, если apk это позволяет. Позже — вынести файлы с Pages. |
| CI-1 | Закрытый ключ подписи apk лежит в контейнере, где исполняется APKBUILD программы (`check()` тоже). | высокая | Сборка без ключа (одноразовый ключ сборки), подпись отдельным заданием, которое не исполняет код программ. |
| PKG-1 | Индекс apk берёт любой `.apk` из любого репозитория организации без проверки, кто вправе публиковать имя, и без сверки digest. | высокая | Колонка apk в `publishers.conf`, проверка имени из `.PKGINFO`, сверка digest выпуска. |
| PKG-3 | Ошибка API GitHub считается «нет выпусков» — репозиторий выпадает из apt и Flatpak до следующего прогона. | высокая | Проверять успех каждого запроса, при сбое — падать, не публиковать. |
| PKG-8, + | Кэш apk по имени файла: заменённые и отозванные файлы остаются навсегда; оборванная загрузка остаётся «целой»; заменённый файл выпадает из публикации. | средняя | Индекс из текущего списка файлов выпусков с digest; загрузка во временный файл с проверкой. |
| + | `build-apk.sh:59` каждая архитектура перезаписывает `SHA256SUMS` только своими пакетами. | средняя | Суммы — один раз после всех сборок. |
| + | Перебор страниц выпусков останавливается на странице без подходящих файлов (`build.sh:63`, `build-apt.sh:43`). | средняя | Останавливаться только на пустой странице. |
| PKG-5 | Если новейший Flatpak не прошёл проверку, программа пропадает из репозитория. | средняя | Брать предыдущий проверенный выпуск. |
| PKG-4 | Метапакеты пересобираются с новыми байтами при той же версии. | средняя | Не перезаписывать опубликованное; воспроизводимое время. |
| CI-2 | Загрузка apk в выпуск без повтора и сверки digest. | средняя | Как в `deb.yml`: сверка и ограниченный повтор. |
| PKG-6, PKG-7, CI-3, CI-4, PKG-10 | Расписание срабатывает реже, кэш на каждый прогон, плавающие образы, `ref: v1`, нет постраничного перебора репозиториев. | низкая | По ходу. |

Изменения `ci` вступают в силу только при переносе тега `v1` — это выпуск,
**нужно твоё одобрение**.

## Волна 1 — оболочка: обновление, сеанс, корень

| ID | Что | Важность |
|---|---|---|
| SH-2 + | Откат после неудачной загрузки ставит все пакеты снимка из файлов и замораживает системные пакеты удержаниями `><Q1` в `/etc/apk/world`; откат игнорирует ошибки восстановления, сообщает об успехе и может удалить снимок; новые зависимости не убираются; тайм-аут проверки здоровья обрывает её без отката и без отметки. | **высокая** |
| SH-1 | `haltia-sleep` работает в SCHED_FIFO, и все его дети — включая ночной `apk upgrade` — тоже. | высокая |
| SH-3 | Устаревший pid-файл: после повторного использования pid `haltia-restart` убивает чужой процесс, вплоть до панели и всего сеанса. | высокая |
| SH-8 | Корневой цикл кнопки питания читает файл из дома пользователя без защиты: FIFO его вешает, ссылка на `/dev/zero` — съедает память. | средняя |
| SH-7 | `haltia-session` при сбое `fork` крутит ядро на 100% от root, экран чёрный. | средняя |
| SH-6 | Демоны сеанса (`haltia-close`, `haltia-home`, `haltia-focus watch`, `haltia-volume`, `haltia-rotate`) и touchguard не перезапускаются при падении. | средняя |
| SH-4 | Настройки строят все страницы и запускают ~15 команд (три — Python через doas) на главном потоке; во время обновления окно подвисает каждые 2 с. | средняя |
| SH-11, SH-14 | Сигнал панели без проверки в `haltia-apps reload`; гонка блокировки обновления → ложный откат после трёх загрузок. | средняя / низкая |
| SH-5, SH-9, SH-10, SH-12, SH-13, SH-15 | Опрос вместо событий, всплеск процессов на кнопке громкости, знание устройства в оболочке, журналы без предела, утечка в phoc. | низкая |

Проверка — только на планшете: откат и автообновление нельзя проверить без
живого `apk`.

## Исполнители (ADR 0005, 0008)

- **Волна 0:** Claude (архитектура подписи, публикация) — диспетчер, ревью
  свежим Claude; перенос `v1` — по твоему одобрению.
- **Волна 1:** живой сеанс оболочки с планшетом (`needs:tablet`), Claude.
- **Волна 2:** модуль картинок и FIL-1/2 — Claude; мелкие правки — Codex.
- **Волна 3:** механические правки (тайм-ауты, атомарная запись, предел
  пикселей, проверки данных) — Codex и Grok через диспетчер; VID-1, MUS-2,
  паттерны потоков — Claude.

Звонки остаются главным приоритетом: аудит не трогает устройство и
мессенджер и идёт параллельно через диспетчер (не больше двух задач).
