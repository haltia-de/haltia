# Открытые оркестраторы агентов: годятся ли Haltia (21 октября 2026)

Второй обзор за день. Первый (утром) сравнивал по описаниям; этот — по
требованиям, которые сложились после ADR 0005–0010, и по документации и коду
кандидатов.

## Наши требования

1. Задачи — Issue в 17 репозиториях организации, запуск по метке
   (`agent:ready`), модель — по метке `model:*`.
2. Исполнители — CLI по подписке: Claude Code, Codex, Grok. Без ключей API.
3. Работа на ПК сборки, не в облаке; таймер systemd.
4. Исполнитель не получает git и GitHub: коммит, пуш, PR и метки делает
   оркестратор (ADR 0006).
5. Песочница: пустой домашний каталог, скрытые ключи подписи и сокеты,
   свои пространства имён; сеть — только поиск документации (ADR 0010).
6. Не больше двух одновременно и одного на репозиторий; лимит подписки —
   `agent:blocked` без смены модели.
7. Ревью по иерархии моделей (ADR 0008), слияние по правилам ADR 0009,
   выпуск только с одобрения человека.
8. Задачи с планшетом — живым сеансам; живые сеансы в herdr (ADR 0007).

## Выводы

- **Ни один не закрывает требования 4 и 5 из коробки.** Sortie ближе всех по
  модели (метки, много репозиториев, локальные CLI, git в крючках
  оркестратора), но песочницу прямо не берёт на себя, а адаптер Claude
  принимает только режим обхода подтверждений. Чтобы взять Sortie, пришлось
  бы заново сделать то, что уже сделано: обёртку bwrap через `agent.command`,
  копию без `.git` (его рабочая папка — обычный клон, и крючки git после
  агента — та же дыра, что закрыта в ADR 0006), иерархию ревью, правила
  слияния, `needs:tablet`.
- **gh-aw** ближе всех по безопасности: агент только читает, записи
  делают отдельные задания, сеть через файрвол с белым списком, токены у
  прокси. Но он работает в Actions и требует ключи API: это оплата за
  токены, а ADR 0005 строится на подписках. Как образец — полезен.
- **Настольные** (Orchestrator.inc, Vibe Kanban, Claude Squad) — для
  человека за экраном, без запуска по Issue; у нас эту роль играет herdr.
- **baton, Symphony** — узкие или только спецификация.

## Рекомендация

Оставить свой диспетчер: около 600 строк без зависимостей, точно под наши
ADR. Взять идеи:

1. **Из Sortie:**
   - обратная связь после PR: падение CI и замечания ревью возвращаются
     исполнителю как продолжение задачи;
   - самопроверка исполнителя перед «done»;
   - сигнал «менять нечего» как законный итог, не ошибка;
   - отказ на вопросы агента, на которые может ответить только человек;
   - сверка состояния после перезапуска;
   - `--dry-run` и `validate` конфигурации.
2. **Из gh-aw:**
   - шаг проверки diff на угрозы между исполнителем и пушем (секреты,
     изменения `.github/workflows`, бинарники);
   - сеть исполнителя через прокси с белым списком доменов вместо
     полного выхода.

Вернуться к Sortie стоит, если понадобится обратная связь CI и
авто-слияние в большом объёме: тогда сравнить стоимость доработки своего
диспетчера с обёрткой Sortie нашей песочницей.
