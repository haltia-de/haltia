# Штатная прошивка TB-J606L через Lenovo Software Fix

Проверено 24 октября 2026. Связано с
[задачей устройства № 4](https://github.com/haltia-de/device-lenovo-tb-j606l/issues/4)
и [планом порта](../plans/tab-p11.md).

## Результат

У Lenovo документировано скачивание прошивки по выбранной модели до
операции Rescue. Найдены официальный установщик и руководство; оба
скачаны и сверены с SHA256 Lenovo. Установщик распакован как архив,
его программы не запускались. Прямой URL пакета
`TB-J606L_S320317_230810_ROW` пока не получен. Наличие этой сборки
в текущем каталоге клиента не подтверждено.

Это уточняет блокировку: не доказано отсутствие штатного пакета или
невозможность скачать его без прошивки. Не завершён именно доступ
к каталогу и получение проверяемых образов.

Прямые загрузки с домена Lenovo вернули HTTP 200; фактические размеры
и вычисленные SHA256 совпали с опубликованными значениями:

По руководству: клиент поддерживает Windows 10/11 x64 (стр. 4).
Ручной выбор планшета: `Tablet` → `Input Serial Number` →
`How to find SN?` → `Manual Selection` (стр. 50–51).
Раздел ручного выбора описывает подбор модели и параметров, затем
`Download`; `Rescue` становится доступной после загрузки (стр. 35–37).
`Download Center` хранит отдельный список скачанных пакетов и позволяет
изменить каталог через `Change` (стр. 23–24).
Источник — [официальный PDF](https://download.lenovo.com/consumer/mobiles/software_fix_user_guide-v7.6.0_english.pdf).

Практический вывод для следующей проверки: оставить USB планшета
отключённым, выбрать именно TB-J606L вручную и остановиться после
получения архива. Этот вывод следует из последовательности руководства;
сам клиент на Windows в этом исследовании не запускался. Выбор
TB-J606L и доступность старой сборки в живом списке ещё надо проверить.

## Статический разбор клиента на Linux

Источником следующих наблюдений является
[проверенный установщик](https://download.lenovo.com/consumer/mobiles/software_fix_v7.6.2.10_setup.exe)
с SHA256 из таблицы. `7z` распаковал NSIS-архив: 263 файла, около
253 МБ. Не найдено файлов с именами J606, firehose, расширениями
`.mbn`/`.elf` или `rawprogram`; это проверка имён, не доказательство
отсутствия упакованных ресурсов.

В `Software Fix.exe.config` указан `BaseHttpUrl=https://lsa.lenovo.com`.
IL методов `get_ServiceBaseUrl` и `get_ServiceInterfaceUrl` из
`lenovo.mbg.service.common.utilities.dll` даёт базу API `/Interface`.
В `lenovo.mbg.service.lmsa.flash.dll` найдены адреса:

- `/rescueDevice/getModelNames.jhtml`;
- `/rescueDevice/getRescueModelNames.jhtml`;
- `/rescueDevice/getRomMatchParams.jhtml`;
- `/rescueDevice/getResource.jhtml` — ручной подбор;
- `/rescueDevice/getNewResource.jhtml` — автоматический подбор.

Это адреса каталога и подбора, не прямые URL образов. В том же
установщике `CreateClientRequestFinger` строит RSA-шифрованную строку
из времени, заголовка Authorization и имени API. `RSAEncrypt`
использует PKCS#1 v1.5, UTF-8 и base64. `GetLastSegmentForLog`
заменяет `.jhtml` в последней части URL на `interface`, поэтому
для начального вызова имя равно `initTokeninterface`. Заголовок
`X-Device-Fingerprint` связан с выданным клиенту токеном; строка
`Missing device fingerprint` сама по себе не доказывает необходимость
серийного номера планшета. Обнаруженный вызов `set_JWT_TOKEN` в
основном приложении принадлежит `LoginByLenovoID`. Наличие старых
guest/initToken маршрутов не доказывает работоспособность входа гостем.

## Проверенные ответы сервера

На Linux выполнены минимальные запросы к
[официальной базе API](https://lsa.lenovo.com/Interface/).
Использовался новый случайный client UUID, без серийного номера,
IMEI, данных планшета или учётной записи. Полученные ответы сохранены
только локально; закрытые значения в эту записку не входят.

| Запрос | Фактический ответ |
|---|---|
| GET `rescueDevice/getModelNames.jhtml` | HTTP 200, code `410`, `Missing device fingerprint.` |
| GET `rescueDevice/getRescueModelNames.jhtml` | То же |
| GET `rescueDevice/getRomMatchParams.jhtml?modelName=TB-J606L` | То же |
| POST `common/rsa.jhtml`, JSON `{}` | HTTP 200, code `0000`, публичный ключ RSA в `desc` |
| POST `user/guestLogin.jhtml`, обычная обёртка client/dparams и случайный accountId | HTTP 200, code `410`, `Missing device fingerprint.` |
| POST `client/initToken.jhtml`, обычная обёртка и случайный clientUUID | То же |
| POST `client/initToken.jhtml`, та же обёртка, пустой Authorization и RSA-fingerprint по алгоритму клиента | HTTP 200, code `403`, `Invalid token.` |
| POST `user/guestLogin.jhtml`, та же обёртка, пустой Authorization и RSA-fingerprint по алгоритму клиента | HTTP 200, code `403`, `Invalid token.` |

Обёртка client/dparams/language/windowsInfo восстановлена по
`RequestModel` проверенного установщика. Маршрут `/lmsa-web/...`
перенаправляет к странице входа, поэтому он не является найденным
публичным API. Поддельные токены, чужие учётные данные, обход проверок
и вход в Lenovo ID не применялись. Протокол пока воспроизведён
частично: корректно сформированный fingerprint с пустым Authorization
перевёл ответ с `Missing device fingerprint` на явный `Invalid token`.
Ключ RSA получался заново, для каждого запроса использовалось свежее
время. Сессию гостя сервер не выдал. Это подтверждает отказ по токену
для проверенной последовательности; оно не доказывает отсутствие
другого штатного начального обмена. Притворяться владельцем выданного
токена или подменять полномочия не требуется для исследования и не
делалось.

## Чем продолжать разбор устройства

1. Следующий прямой путь — ручная загрузка по модели официальным
   клиентом с отключённым планшетом. Зафиксировать предложенную
   сборку, URL/хэш пакета и параметры выбора. Если требуется вход
   Lenovo ID, его выполняет владелец; исследование не создаёт аккаунт.
2. Более новая официальная сборка J606L полезна для изучения формата
   boot и вариантов DTS, но не считается копией установленной
   `S320317` или подтверждением платы конкретного экземпляра.
3. [Lenovo Open Source Portal](https://support.lenovo.com/is/ko/solutions/ht511330-lenovo-open-source-portal)
   отдельно перечисляет исходники TB-J606L версии
   `s000157_201116_row` от 26 января 2021. Это дополнительный
   источник для исследования платы. Архив получен и разобран
   [отдельным исследованием](2026-10-24-j606l-board-sources.md);
   он старше текущей сборки и не заменяет её загрузочные образы.
4. Если пакет точной сборки доступен через зеркало, размещение на
   зеркале и подлинность образов надо проверять раздельно. AOSP
   определяет VBMeta digest как хэш корневой и всех связанных
   структур VBMeta и даёт `avbtool calculate_vbmeta_digest` для
   вычисления из файлов. Хэш кандидата можно сравнить с локальным
   эталоном текущего Android, затем проверить boot/dtbo по дескрипторам
   совпавших метаданных. Самоподпись неизвестным вложенным ключом
   такой эталон не заменяет.
   Источники: [AOSP, VBMeta digest](https://android.googlesource.com/platform/external/avb/+/761178607206f4cb2af79ed9eec52d8cbd814adb/README.md#the-vbmeta-digest),
   [реализация проверки образов](https://android.googlesource.com/platform/external/avb/+/761178607206f4cb2af79ed9eec52d8cbd814adb/avbtool.py).

Пункт 4 — предлагаемый следующий способ проверки, а не выполненная
аутентификация пакета. На разблокированном планшете сравнение с
текущим Android означает совпадение с выбранным локальным эталоном,
не независимую аппаратную аттестацию. VBMeta также не удостоверяет
произвольный EDL-программатор и не заменяет копии modemst/persist.

## Границы проверки

В этом исследовании не было доступа к планшету, перезагрузок, загрузки
ядра, записи разделов, запуска Windows-программ или многогигабайтного
скачивания прошивки. Прямой URL штатного ROM, состав boot/DTBO и
совместимый программатор пока не подтверждены. Получение штатного
архива позволит продолжить задачу № 4; задачу резервирования
идентификационных разделов оно само по себе не закрывает.
