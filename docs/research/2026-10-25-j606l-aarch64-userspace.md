# J606L: доступность aarch64 userspace Haltia

25 октября 2026. Проверка следующего этапа после RAM-загрузки ядра.
Это анализ пакетов на компьютере; планшет не открывался, программы на
ARM64 не запускались и rootfs на устройство не записывался.

## Что проверено

В изолированном amd64-контейнере Alpine 3.24 выполнено разрешение
зависимостей с целевой архитектурой **aarch64** для `phoc`, `seatd`,
`libinput`, `haltia-shell` и `py3-haltia-kit`. APK работал с пустой
пользовательской базой в tmpfs, затем с `--simulate`; установка пакетов
и выполнение их scripts не выполнялись. Контейнер без capabilities,
с read-only корнем и без доступа к USB.

| Компонент | Версия из принятого решения APK |
|---|---|
| apk-tools проверяющего контейнера | 3.0.8-r0 |
| phoc | 0.55.1-r0 |
| haltia-shell | 2.12.2-r0 |
| py3-haltia-kit | 2.3.1-r0 |
| seatd | 0.9.3-r0 |
| libinput | 1.31.3-r0 |
| Mesa | 26.1.6-r0 |

Разрешено **328 пакетов**, metadata installed size **513.0 MiB**.
Это оценка распакованного содержимого, а не измеренный размер готового
rootfs или сжатого initramfs. Ошибок зависимостей и предупреждений о
подписях в успешном проходе нет.

Использованы main/community Alpine v3.24 и
`https://haltia-de.github.io/packages/alpine/v3.24`.
Проверка TLS и подписей индексов включена. SHA256 публичного ключа Haltia:
`be069663c6744f280633148f48d2053d6a83e2f4502f7070bb616b758e0b1431`.
При проверке другой архитектуры нужно добавить её штатные ключи из
`/usr/share/apk/keys/aarch64` закреплённого Alpine image: набора ключей
amd64 по умолчанию оказалось недостаточно. Обход доверия не применялся.

Проверяющий image ID:
`sha256:294b683cb724975bec92580e1e685676bd4b50bda910ddb8c51d4cabeaec77e6`.
Индексы актуальны только на дату проверки; готовые APK и их хэши предстоит
отдельно получить, проверить и закрепить при сборке rootfs. Зелёный solver
не доказывает установку, работу phoc или совместимость аппаратуры.

## Следствия для образа J606L

Общую оболочку можно брать из aarch64-репозитория, без копирования её
исходников в устройство. У J606L должен быть собственный профиль и замок
пакетов. Armv7 `linux-port/apps/packages.lock` B8000-H содержит хэши
других архитектурных файлов и не переносится в J606L как готовый замок.

Прочитан builder B8000-H на pin
`b5013db3f0806fb2d516a0cfa33858c2d8bfc159`: его generic набор Alpine,
seatd/libinput и запуск общей оболочки полезны как ориентир. MTK-модули,
RDMA-регистры, hybris/phoc-gpu и настройки B8000-H в новый профиль
не переносятся. Первый показ J606L по плану остаётся phoc на DRM.

Boot A/B имеют по 100663296 байт. Нельзя предполагать, что весь userspace
вместится в диагностический boot: до выбора схемы нужны отдельный rootfs,
измерение размера и проверенный план хранения. Разрешение зависимостей
не является основанием менять GPT или userdata. Сначала завершается
ограниченная RAM-проба и возврат B, затем отдельно проверяются DRM/панель,
userspace и постоянное размещение Linux.
