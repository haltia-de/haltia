# Изолированная функциональная проверка desktop-пакетов

Требуются Python 3.12+, Docker, общедоступный ключ Haltia и доступ к сети только для установки зависимостей контейнера. Хостовые пакеты, пользовательские приложения, домашний каталог и графический сеанс не используются. Рабочий каталог должен быть отдельным и иметь достаточно места (около 1 ГБ с контейнером). Не помещайте в него секреты: он целиком монтируется в тестовый контейнер.

Скопируйте `gtk_probe.py` и `run-functional.py` в отдельный рабочий каталог. Для дополнительных тестов исходников также скопируйте `snapshot-sources.py` и создайте снимки соседних репозиториев:

```sh
rtk proxy python3 snapshot-sources.py --source-root /path/to/haltia-de --output /path/to/validation
rtk proxy python3 run-functional.py --workdir /path/to/validation --keyring keys/haltia-archive-keyring.gpg
```

Контейнер Ubuntu 26.04 устанавливает шесть программ и kit из подписанного официального apt-репозитория resolute. После установки контейнер отключается от сети. Затем дважды запускает каждый интерфейс на Xvfb: навигация по доступным настройкам, поиск при отключённой сети, безопасные локальные переключатели; Раскраска — открытие встроенной картинки, GTK-событие рисования, проверка прогресса после нового запуска. Ни один сценарий не нажимает вход, отправку, звонок или включение веб-доступа.

`summary.json` — общий результат. В `screens/` — снимки реальных окон и JSON с видимыми надписями, кнопками и утверждениями. `source-*.log` — тесты зафиксированных исходников. `text` и `calendar` не имеют test suite; для них выполняется только компиляция. Снимок исходников — это `git archive HEAD`, без незакоммиченных правок.

Ограничения: это контролируемая офлайн-проверка на ПК, не планшетная и не проверка сервисов. Работа с аккаунтами, звук, камера и desktop-порталы требуют отдельных сценариев. Тест камеры использует только `videotestsrc`, если зависимости доступны. Снимки следует визуально проверить перед выводом об интерфейсе. Контейнер получает уникальное имя и удаляется в `finally` только после успешного создания этим запуском; данные и журналы остаются в рабочем каталоге. Не запускайте два экземпляра harness одновременно.

## Локальный кандидат Раскраски

Для отдельной проверки исправления берётся точный commit; каталог checkout не меняется. Сборка использует штатный `dpkg-buildpackage -b -us -uc`, без подписи, выпуска, тега и изменения версии. Затем тот же deb ставится в одноразовые noble/resolute/trixie. Проверяются реальные GTK-события рисования, состояние после нового процесса и завершение SIGTERM/SIGINT. Опубликованный пакет не заменяется.

```sh
rtk proxy python3 prepare-paint-candidate.py --repo /path/to/paint --commit COMMIT_SHA --workdir /path/to/fresh-candidate-validation --keyring keys/haltia-archive-keyring.gpg
```

`source.json`, `build.results.json` и `candidate.results.json` фиксируют исходник, sha256 локального unsigned deb и результаты. Версия внутри кандидата может совпадать с опубликованной: всегда различайте их по commit и sha256. Скрипт подготовки — переносимая обёртка, проверенная синтаксически; содержащиеся в ней команды сборки и проверки выполнены отдельно в этой сессии.

`run-functional.py` устанавливает актуальные подписанные версии; он не закрепляет исторический снимок apt. Для точного повторения старых результатов сохраняйте проверенные артефакты и подписанные индексы. Непройденные обязательные проверки записываются в JSON и приводят к ненулевому exit runner. Неудачная сборка или отсутствие deb также возвращают ненулевой код.

## Проверка изоляции runner

```sh
rtk proxy python3 test_runner_isolation.py
```

17 тестов вызывают runner через поддельный CLI `docker` из временного PATH. Реальный Docker не вызывается. Проверяются коллизия создания, отказ установки, провал обязательной проверки, уникальность имён, очистка только своих контейнеров и коды выхода build. `build.py` использует Docker `run --rm` без фиксированного имени и не удаляет контейнеры отдельной командой.

Исправленная переносимая версия проверена синтаксически и этими 17 тестами границы subprocess; полный GTK/source/container прогон относится к предыдущим реально выполненным runner и не повторялся после этого рефакторинга. Исторические журналы сохранены без изменений.

## Свежие source suites из main

Локальный HEAD может отставать или расходиться с main. Для текущего состояния используйте GitHub API и точные архивы:

```sh
rtk proxy python3 snapshot-github-main.py --output /path/to/fresh-source-validation
rtk proxy python3 run-source-suites.py --workdir /path/to/fresh-source-validation
```

Требуется `gh` с доступом к публичному GitHub API. Endpoint содержит полный `repos/haltia-de/<repo>`; команда `gh api` не поддерживает флаг `-R`. Каждый SHA фиксируется до скачивания архива. Runner проверяет все существующие test scripts Files и suites Mail/Firefox/Camera/Text/Calendar/kit; текущие Text/Calendar уже имеют тесты. Исторические утверждения об отсутствии suites относятся только к прежним старым local HEAD. Снимки и код используют только отдельный рабочий каталог, существующие checkout не меняются.

## Обязательная полнота и отказ очистки

```sh
rtk proxy python3 test_probe_completion.py
rtk proxy python3 test_snapshot_ownership.py
rtk proxy python3 test_runner_isolation.py
```

7 тестов проверяют реальную границу завершения gtk_probe без GTK: ранний app.run failure, пустой список результатов и отсутствие любого обязательного этапа возвращают ошибку. Успех требует app.run=0, всех обязательных этапов и отсутствия FAIL. Ещё 4 теста проверяют отказ обоих snapshot-helper при существующем sources или manifest до вызовов Git/GitHub. 17 fake-Docker тестов включают отказ очистки: docker rm nonzero записывается как container_cleanup FAIL и приводит к nonzero runner. Итого 28 тестов. Новые негативные regression сначала воспроизвели дефекты, затем прошли после исправления.

Оба snapshot-helper требуют новый каталог без sources и source-manifest.json; смешивание старого и нового дерева не допускается. После этих исправлений полноты/cleanup/snapshot полноценные GTK/container прогоны не повторялись: проверены только указанные границы и синтаксис. Исторические журналы остаются отдельным доказательством прежних запусков.
